- **전 파일이 `<!DOCTYPE level2 SYSTEM "history.dtd">`(또는 level1) 를 가진다.** 외부 DTD 를 가리키는 SYSTEM 선언이다. `<!ENTITY` 선언은 673개 파일 전체에서 0건이다(전수 확인). → T209 가 "DOCTYPE 이면 거부"로 구현하면 **실제 파일을 전부 거부한다.** 파서는 DTD 를 읽지 않고 엔티티를 풀지 않는 방식(표준 `ElementTree` 는 외부 DTD 를 가져오지 않는다)으로 읽고, `<!ENTITY` 가 있을 때만 거부하는 쪽이 맞다. T209 명세 수정 필요.
- 기사 계층: `level2`(왕·권) → `level3`(월) → `level4`(일) → `level5`(기사). 파일마다 최상위 2개 단계는 `front`·`text` 가 있다.

## 음력 여부
`dateOccured[@type="서기"]/@date` 값 뒤에 붙는 `L0` 는 **음력 날짜 표지로 보인다(추정)**. 근거: 태조 즉위 기사의 값이 `1392-07-17L0` 이고 같은 기사의 `재위연도`·`간지`·본문(`十七日丙申`)이 7월 17일이다. 태조 즉위는 역사적으로 음력 7월 17일이므로 연-월-일 숫자는 양력 변환 전의 음력 일자다. 표본(파일 1/6)에서 `L0` 83,756건 · `L1` 2,326건이다. `L1` 은 윤달로 본다 — 근거: `2nd_waa_101.xml` 의 `date="1392-12-04L1"` 이 `재위연도` "태조 1년 **윤**12월 4일" 과 짝을 이룬다(다른 파일의 전수 대조는 안 했다). locator 가 `재위연도` 표기를 쓰므로 윤달 표시는 그대로 남는다. 정확한 정의는 [확인 필요] — `history.dtd` 안에서 `L0` 설명을 찾지 못했다. → locator 에는 "음력" 을 명시하고 양력 변환은 하지 않는다.

## 원문 URL
`https://sillok.history.go.kr/id/{기사 ID}` — 실제 확인: `waa_10107017_001` 로 GET(User-Agent 지정) 시 200, 응답 본문에 `수창궁`·`壽昌宮`·기사 ID 가 들어 있고, 존재하지 않는 ID(`waa_99999999_999`)는 제목이 다른 오류 페이지로 응답했다. User-Agent 없이 `curl -sI` 는 400 이었다. 사이트 이용약관·접속 빈도 제한은 [확인 필요]이므로 수집기는 URL 문자열만 만들고 호출하지 않는다.

## locator 형식 결정
`{재위연도 표기}(음력) · {기사 ID}` — 예: `태조 1년 7월 17일(음력) · waa_10107017_001`. `재위연도` 값에 왕 이름이 이미 들어 있으므로(`태조 1년 …`) 왕대를 따로 앞에 붙이지 않는다("태조 태조" 중복 방지). 값은 level4 에서 가져오고 "(음력)" 은 수집기가 붙인다. 기사 ID 는 URL 과 `source_id`(`sillok:{id}`) 에 쓴다.
