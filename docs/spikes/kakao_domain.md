# T404 — 카카오 지도 JS 키 도메인 등록

## ① 출처
- A. 앱 설정(플랫폼 키·JavaScript SDK 도메인): https://developers.kakao.com/docs/latest/ko/app-setting/app
- B. 카카오맵 공통(사용 방법·이용 정책·쿼터): https://developers.kakao.com/docs/latest/ko/kakaomap/common
- C. 쿼터 표: https://developers.kakao.com/docs/latest/ko/getting-started/quota
- D. 지도 Web API 가이드(준비하기): https://apis.map.kakao.com/web/guide/
- E. 지도 Web API 레퍼런스(`kakao.maps.load`): https://apis.map.kakao.com/web/documentation/
- 시도했으나 404: `.../ko/kakaomap/maps-web`, `.../ko/getting-started/app`, `.../ko/platform-key/app-key` (경로 추측이 틀렸음. 위 5개가 실제 본문).
- 문서 본문에 "2026년 7월 21일부터 카카오맵 API 사용 방법과 무료 쿼터 제공 방식이 변경"이라는 안내가 있다(B). 변경 공지 본문은 읽지 않았다 `[확인 필요]`.

## ② 도메인 등록 위치·형식
- 위치: 앱 관리 페이지 [앱] > [플랫폼 키] > [JavaScript 키] > [JavaScript SDK 도메인] (A, D).
- 규칙(A): `http://`, `https://`, `file://` 형식 등록 가능. **http 와 https 는 한쪽만 등록해도 둘 다 사용 가능.** 등록하지 않은 도메인의 요청은 거절된다("등록된 사이트 도메인에서만 지도 API를 사용할 수 있다", D).
- 포트: 규칙 문장에는 포트 언급이 없다. 가이드 예시가 `http://localhost:8080` 을 "등록한 도메인"으로 쓴다(D). 즉 로컬 포트 포함 등록은 예시로 확인됨. 와일드카드 포트 규칙은 문서에 없음 `[확인 필요]`.
- 경로: JavaScript SDK 도메인 항목에는 경로 규칙이 없다. (제품 링크의 "웹 도메인" 항목은 경로를 제외하고 등록된다고 되어 있으나 별개 설정이다.)
- 주의: 제품 링크용 "웹 도메인"([앱] > [제품 링크 관리])은 **다른 설정**이다. 지도에는 JavaScript SDK 도메인만 필요하다(A).
- 잘못 등록했을 때 에러: `invalid android_key_hash or ios_bundle_id or web_site_url` (A). 실제 요청 시 `dapi.kakao.com` 이 인증 없는 요청에 401 을 돌려주는 것은 확인했다(키 없이 호출, 키 값 불필요).

## ③ 등록 가능 수
- 최대 10개. 더 필요하면 데브톡 문의 (A).
- 플랫폼 키(JavaScript 키) 자체는 종류별 최대 5개까지 추가 가능, 키 복제 생성 가능(A).

## ④ 무료 사용량·초과 시 동작
- 지도 Web(JavaScript) SDK 일간 쿼터 300,000건 (C). 월간은 "전체 API 3,000,000건" 합산 항목만 있다. 월간 쿼터는 "추후 변경될 수 있음"이라고 명시(C).
- 무료 쿼터는 **개발자 계정 기준 카카오맵 API 를 처음 활성화한 앱 하나에만** 제공된다. 두 번째 앱부터는 비즈월렛 연결 후 유료 API 설정이 필요하다(B).
- 활성화: [앱] > [카카오맵] > [사용 설정] > [상태] ON (B). 켜지 않으면 쓸 수 없다.
- 초과 시: **429 Too Many Request** (B). 유료 API 를 설정하지 않으면 지도 호출이 실패한다 → 화면은 SVG 폴백으로 내려가야 한다(D11).
- "건"의 집계 단위(지도 로드 1회가 몇 건인지, 타일 요청 포함 여부)는 문서에 없다 `[확인 필요]`. 사용량은 [통계] > [쿼터]에서 볼 수 있다(B).

## ⑤ JS 키 노출은 정상인가·보호 수단
- 설계상 정상: JavaScript 키는 웹 페이지에 포함해 쓰는 값이며(`appkey=` 쿼리로 SDK 스크립트 URL 에 들어감, D), 보호는 **등록된 JavaScript SDK 도메인에서만 사용 가능**이라는 도메인 제한이다(A).
- 단 Origin/Referer 기반 제한이므로 서버 간 호출로 위조 가능한지는 문서에 없다 `[확인 필요]`. 따라서 쿼터 소진(429)을 전제로 한다.
- 보호 수단: ① 운영·로컬 도메인만 등록 ② 노출이 의심되면 [복제 키 생성]으로 설정을 유지한 채 키 값만 교체(A) ③ 일간 쿼터 모니터링 ④ **REST API 키는 지도 SDK 에 쓰지 않는다**(B: 잘못된 키 종류는 에러). REST 키·어드민 키는 프런트에 넣지 않는다.
- 저장소: `config.local.js` 는 gitignore 대상 개인 파일이다(존재 확인만). 배포 시 키는 빌드 시점 주입(T424 에서 정함). 값을 커밋·로그에 남기지 않는다(규칙 1).

## ⑥ 미리보기 도메인 등록 필요 여부
- 미리보기(Netlify 배포 미리보기 등 임의 서브도메인)에서 지도를 쓰려면 그 호스트가 등록돼 있어야 한다. 등록 수는 10개로 제한이라 미리보기마다 등록하는 것은 비현실적이다.
- 와일드카드(`*`) 포함 도메인 등록은 **가능**하지만 (A) 조건이 있다: **비즈 앱**에서만 와일드카드 서브도메인 설정 가능(A "비즈 앱" 절), 와일드카드 도메인은 **최초 도메인으로 추가할 수 없고** 다른 도메인을 먼저 등록한 뒤 추가해야 한다(A, 제품 링크 웹 도메인 절의 규칙이며 JavaScript SDK 도메인에도 같은 규칙이 적용되는지는 문서에 명시 없음 `[확인 필요]`).
- 비즈 앱 전환 요건(비즈니스 정보 등록 등)이 해커톤 팀에 해당하는지 `[확인 필요]`.
- 결론: **운영 도메인 + `http://localhost:<포트>` 만 등록**한다. 미리보기 배포에서는 지도 대신 SVG 폴백(D11, 엣지 케이스 규정대로). 와일드카드는 비즈 앱 전환이 쉬울 때만 선택.

## ⑦ JS 키 형식
- 공식 문서에 JavaScript 키의 형식(길이·문자 구성)이 **없다**. → 빌드 스크립트는 **형식 검증 안 함, 길이 상한만**(예: 128자 이하, 공백·따옴표·`<`·`&` 같은 문자 금지 정도의 안전 점검). 특정 자릿수 정규식을 만들지 않는다.

## ⑧ SDK 가 불러오는 출처 (CSP)
- 문서로 확인된 것: 스크립트 `https://dapi.kakao.com/v2/maps/sdk.js?appkey=...` (D, E는 `//dapi.kakao.com` 로 적혀 있음). `autoload=false` 를 쓰면 스크립트 로드 후 `kakao.maps.load(callback)` 에서 콜백으로 객체를 쓴다(E: "스크립트의 로딩이 끝나기 전에 객체에 접근하면 에러", "autoload=false 를 지정해야 한다"). 코드의 `SDK_ORIGIN` 과 일치하며, `kakao-sdk.js` 의 `[확인 필요]` 주석(autoload=false 사용법)은 E 로 해소됨.
- 서비스 라이브러리는 `&libraries=services` 등 추가 파라미터(D). 우리는 쓰지 않는다.
- **타일·이미지·로그 요청 호스트는 문서에 없다** `[확인 필요]`. CSP 목록은 문서가 아니라 **실제 브라우저 네트워크 로그**(H6 단계 6)로 확정해야 한다. 그 전까지 `script-src https://dapi.kakao.com` 만 확정이고 `img-src`·`connect-src` 는 비워 두거나 실측 후 채운다. 추측으로 와일드카드를 넣지 않는다.
- http 로 로드하는 예(`http://dapi.kakao.com`)가 레퍼런스에 있으나 배포는 https 이므로 `https://` 를 쓴다(혼합 콘텐츠 방지).

## ⑨ H6 절차 체크리스트 (사람이 실행, 번호 순서)
1. 카카오 개발자(https://developers.kakao.com) 로그인, 앱 선택. 카카오맵을 이 계정에서 **처음 활성화하는 앱**인지 확인(아니면 무료 쿼터 없음, ④).
2. [앱] > [카카오맵] > [사용 설정] > [상태] 를 ON.
3. [앱] > [플랫폼 키] > [JavaScript 키] 를 열고 [JavaScript SDK 도메인]에 `http://localhost:<로컬 포트>` 등록(예: 가이드 예시 `http://localhost:8080`; 실제 데모 포트로).
4. 같은 곳에 Netlify 운영 도메인(`https://<site>.netlify.app` 또는 커스텀 도메인) 등록. http/https 는 한쪽만 등록해도 된다. 총 10개 이하.
5. (선택) 미리보기용 `*` 와일드카드는 비즈 앱 전환 후, 다른 도메인을 먼저 등록한 뒤에만 시도. 하지 않으면 미리보기는 SVG 폴백.
6. 키를 복사해 로컬은 `config.local.js`(gitignore), 배포는 Netlify 빌드 환경변수로 주입(값은 채팅·커밋·로그에 붙이지 않는다). 운영 URL 에서 지도를 열고 개발자도구 Network 에서 `dapi.kakao.com` 외 호스트(타일·이미지)를 기록해 CSP 목록을 확정(⑧).
7. 운영 URL 과 localhost 둘 다에서 지도가 뜨는지 확인. 등록되지 않은 호스트(예: 다른 포트)에서는 거절되는 것도 한 번 확인.
8. [통계] > [쿼터]에서 지도 SDK 일간 쿼터(300,000건 기준)를 확인하고, 데모 후 소모량을 `docs/status/deploy_*.md` 에 기록.
9. 키 노출이 의심되면 [복제 키 생성]으로 교체하고 이전 키를 삭제(대표 키는 삭제 불가이니 먼저 대표 키 변경).
