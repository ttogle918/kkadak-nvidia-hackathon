## 2. Tavily 이용약관 (출처: https://tavily.com/terms, 발췌·요약은 페이지 읽기 결과)
- **결과 저장·캐시 조항: 명시된 조항을 찾지 못했다.** 허용도 금지도 적혀 있지 않다 → 법적 판단은 하지 않는다. 저장은 정규화 레코드의 짧은 `quote`·URL 로 한정하고(D12 ⑦) 원문 전체는 저장하지 않는다.
- 금지: "license, sublicense, resell, distribute, lease, rent, lend, transfer, assign or otherwise dispose of the Services" — 서비스 재판매·재배포 금지. 우리는 서비스를 재배포하지 않는다.
- 금지: "use Output generated by the AI Functionality to develop models that compete with the Company" — 경쟁 모델 개발에 출력을 쓰지 않는다. 우리는 하지 않는다.
- 금지: 고위험 영역에서 "make automated decisions without human oversight". 우리 레코드는 초안 등급·사람 승인(D2·D12 ④)이다.
- Tavily 는 고객 입력(질의)을 모델 학습·개선에 쓸 수 있다고 적혀 있다 → **질의문에 개인정보·비밀을 넣지 않는다**(우리 질의는 `"{구} 축제 행사 {월}"` 뿐).
- 이 요약은 약관 본문을 직접 인용한 것이 아니라 페이지 읽기 도구의 발췌다. 원문 확인은 사람이 한 번 해 주면 좋다 `[확인 필요]`.

## 4. 사용자 결정 (2026-10-07)
- 마포구 수집 허용(robots.txt `User-agent: *` 의 `Disallow: /` 를 알고 내린 결정). `mapo.json` status=confirmed.
- 구청 도메인 밖 후보 포함: 강남 `visitgangnam.net`(robots.txt 미확인 `[확인 필요]`), 중구 `blog.naver.com/junggu4u`(호스트 전체가 아니라 경로 접두로 제한).
- 파일 형식에 선택 키 `allow_url_prefixes`·`disallow_path_prefixes`·`drop_urls_with_query` 를 추가했다.
- robots.txt 확인(2026-10-07): `visitgangnam.net` 은 `*` 에 `Allow: /`, `/admin` `/set-locale/` `/preview/` `/search?` 만 차단 → `gangnam.json` 에 반영. **`blog.naver.com` 은 "AI 학습·RAG 목적의 봇 접근 엄격 금지"를 적고 GPTBot·ClaudeBot·Claude-SearchBot·PerplexityBot 등을 `Disallow: /` 로 막는다.** 우리 용도(검색 본문을 LLM 으로 추출)는 RAG 성격이라 중구 블로그 포함은 재확인이 필요하다 — `junggu.json` note 에 남겼다.
- 중구 공식 블로그(blog.naver.com/junggu4u) 는 사용자가 제외(2026-10-07): 네이버 robots.txt 의 AI 학습·RAG 금지 때문. 위 '구청 도메인 밖 후보 포함' 항목 중 강남페스티벌만 유효하다.

## 5. 실호출 확인 (2026-10-07, T226, 질의 구마다 `--candidates-only`)
- `include_domains: ["www.junggu.seoul.kr"]`·`["www.gangnam.go.kr","visitgangnam.net"]` 는 `www.` 호스트 그대로 매칭된다. 한국어 질의("강남구 축제 행사 2026년 10월")가 행사 페이지(강남문화재단 축제·행사, 강남페스티벌, 구청 행사 목록)를 위쪽에 가져온다. 강남은 품질 양호, 중구는 공지·보도자료·문화관광 페이지가 섞이고 본문이 짧은(80~200자) 결과가 많다.
- `include_domains: ["www.mapo.go.kr"]` 는 **본 사이트 결과가 0건**, 상위 10건 전부 하위 도메인(council·bid·health·mplib). 마포구청 robots.txt 의 일반 크롤러 전면 차단과 일치 → 마포구는 이 경로로 행사를 못 모은다. 허용 결정과 무관하게 후보 0건. 마포구는 TourAPI·서울 열린데이터광장(D7)·수기로 채운다.
- 서브도메인(`*.mapo.go.kr` 등)이 `include_domains` 에 `mapo.go.kr` 계열로 넘어오므로, 응답 URL 은 코드의 `url_allowed`(호스트 접미 일치 + `allow_url_prefixes`)로 한 번 더 거른다 — 마포는 `allow_url_prefixes` 가 `https://www.mapo.go.kr/` 이라 하위 도메인이 모두 버려진다.
- 크레딧: 세 구 `--candidates-only` 6회 + 마포 확인 1회 = 약 7크레딧(basic 1/회).

## 6. 중구청 보도자료 (사용자 제시, 2026-10-07)
- 사용자가 준 `https://www.junggu.seoul.kr/content.do` 는 `cmsid` 가 없어 "페이지가 존재하지 않습니다" 오류 페이지(HTTP 200)다. 실제 보도자료 게시판은 `/content.do?cmsid=14390`(상세 `&mode=view&cid=…`, 쪽 `&page=N`, 2026-10-07 기준 6,588건·659쪽).
- 이전 조사에서는 메인 페이지 메뉴만 보고 `14390` 을 별도로 확인하지 않았다. 도메인(`www.junggu.seoul.kr`)이 이미 허용 대상이라 검색은 이 게시판을 포함했지만 겨냥하지는 않았다.
- 실측(Tavily 질의 "중구 보도자료 행사 개최 2026년 10월", 1크레딧): 보도자료 목록(`cmsid=14390`, 본문 약 8.6천 자)·뉴스포털(`/news`)·공지사항이 상위에 온다. 목록에는 최근 행사 보도(예: "남산동행 중구민 걷기대회 16일 저녁", "어울림 한마당")가 제목과 게시일로 보이지만, 제목에 **월 없이 일만**("16일")이 적힌 경우가 많다 → 현재 추출 규칙(월 없는 일자는 날짜로 인정하지 않음)에서는 제목만 남고 날짜가 비워진다(안전한 쪽).
- 조치: `junggu.json` 의 `queries` 에 보도자료 질의 `"{gu} 보도자료 행사 개최 {month}"` 를 추가했다(구마다가 아니라 중구만, 호출 +1).
- 후속 제안 `[제안]`: 보도자료 상세 페이지에는 게시일이 있으니, 추출 때 게시일을 `published` 로 받아 "월 없는 일자"를 게시월로 보충하는 규칙을 검토한다(연·월 추정 표시와 함께). 목록 페이지 하나에 행사 여러 건이 섞여 quote 창 안에서 확인되는지는 실제 추출기(T223) 연결 후 확인한다.
- 부가: Tavily 가 `https://junggu.seoul.kr/...`(www 없는 같은 사이트)와 루트 `https://www.junggu.seoul.kr`(슬래시 없음)도 돌려주는데 `url_allowed` 가 현재 버린다(`domains` 가 `www.` 호스트만, 접두가 `…/` 로 끝남). 의도한 보수적 동작이지만 중복 도메인이 늘어나면 허용 목록에 추가할지 정한다.
