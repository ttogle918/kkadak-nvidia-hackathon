# 09. 개발 계획

> 마감일을 아직 모르므로 날짜가 아니라 **순서**로 적었다. 마감이 정해지면 단계마다 날짜를 붙인다.
> 담당은 지금까지 정한 대로 적었다: 이야기 길은 본인, 지금의 한국은 오빠. 나머지는 `[제안]`이다.

## 1. 저장소 구조

현재 레포(CLAUDE.md '레포 구조', D3·D10)를 따른다. `k-context/app, ingest/, web/, policy/` 구조는 쓰지 않는다.

```
core/                  도메인 무관 뼈대 — llm · hitl · guard · audit · policy_proposer
backend/               화면 API + 사람 전용 승인 API (routers/). domains·mcp_server 를 import 하지 않는다
mcp_server/
  tools/               도구 파일당 1개(계획 sprint-2). backend 와 서로 import 하지 않는다
domains/kcontext/
  contract/            공통 계약 타입
  index/               로컬 색인(검색)
  regions              지역 정의 (data/regions/*.json)
  ingest/              [계획 sprint-2] 호스트에서 도는 오프라인 수집기 (D7)
  judge/               [계획 sprint-2] 판정
  geo/                 [계획 sprint-2] 좌표·경로
  pipeline/            [계획 sprint-2] 별도 프로세스(APP_PROCESS_ROLE=agent). kc-bundle/v1 파일을 쓴다
  data/                regions · stories · situations · raw
frontend/k-context/    화면
deploy/openshell/      정책(policy.yaml)·이미지. policy.yaml 은 사람만 고친다
skills/                제품 스킬 (에이전트에게 주는 SKILL.md)
scripts/ eval/ tests/  스크립트 · 평가셋 · pytest(소스 구조를 따라간다)
docs/                  이 문서들
```

- 아래 트리 중 현재 레포에 있는 것은 `core/`, `backend/`, `domains/kcontext/{contract, index, regions, data}`, `mcp_server/`(빈 `tools/` 패키지)뿐이다. `ingest/`·`judge/`·`geo/`·`pipeline/` 와 `mcp_server/tools/` 의 도구 파일은 **계획(sprint-2)** 이다.
- `backend` 와 파이프라인은 `kc-bundle/v1` 파일, audit JSONL, hitl draft 로만 주고받는다(D10).
- 상태 전이(승인·반려)는 `backend` 의 review 라우터에만 둔다(D2).

> ⚠ 미해결 충돌: D7 과 어긋남(수집 위치: 아래 3단계의 수집·구청 게시판·포스터 계획) — 사람 결정 대기

## 2. 단계

각 단계는 "끝났다고 볼 기준"을 만족해야 다음으로 간다. 0단계는 다른 것보다 먼저, 나머지는 겹쳐서 진행한다.

### 0단계. 막히는 것부터 푼다

키 발급과 확인에 시간이 걸리는 것들이다. 가장 먼저 시작한다.

- [ ] 공공데이터포털 TourAPI 활용 신청, 서울 열린데이터광장 인증키, SK open API(TMAP) 키, NVIDIA API 키
- [ ] Brev 인스턴스 단가 확인, 크레딧으로 쓸 수 있는 시간 계산
- [ ] OpenShell 설치, 버전 확인, 빈 샌드박스 하나 띄워 보기
- [ ] 샌드박스 안에서 Nemotron 한 번 불러 보기 ⚠ 미해결 충돌: D1 과 어긋남(`inference.local` 로만) — 사람 결정 대기
- [ ] 공통 계약(`AGENT_CONTEXT.md` 3.3) 두 사람이 읽고 확정
- [ ] `policy.yaml` 관리자 한 명 지정

**끝:** 샌드박스 안의 코드가 프로바이더를 통해 Nemotron의 답을 받는다.

### 1단계. 뼈대

- [ ] 저장소, Dockerfile, DDL로 빈 DB 두 개 만들기
- [ ] FastAPI 뼈대(`backend/`)와 메시지 경로, 이벤트 스트림 ⚠ 미해결 충돌: D10 과 어긋남(세션·SSE) — 사람 결정 대기
- [ ] 화면 뼈대: 대화창, 지도, 카드 자리. Claude Design 결과물을 옮긴다
- [ ] **가짜 데이터로 끝에서 끝까지**: 고정된 카드와 경로를 돌려주는 백엔드에 화면을 붙인다

**끝:** 가짜 데이터로 데모 흐름 전체가 화면에서 돈다. 이후에는 가짜를 하나씩 진짜로 바꾼다.

### 2단계. 일정 이해와 지도 (공통)

## 4. 일하는 규칙

- **공통 계약을 바꾸려면 문서를 먼저 고친다.** 코드에서 필드를 먼저 늘리지 않는다.
- **정책 파일(`deploy/openshell/policy.yaml`)은 사람만 고친다.** 에이전트·dev 는 수정하지 않는다(D7). 다른 사람은 필요한 호스트와 이유를 적어 요청한다.
- **키를 커밋하지 않는다.** `.env`는 `.gitignore`. 공개 전에 커밋 이력을 검사한다.
- **검증 전 자료는 `draft`.** ⚠ 미해결 충돌: D10 과 어긋남 — `draft`→`verified` 승격 경로는 **미정**이다(코드·sprint-2 에 없음). "화면에는 `verified` 만"은 D10 의 제안 지위 카드(출력 묶음·audit·draft 는 제안 지위)와 어긋날 수 있다 `[확인 필요]`.
- **숫자는 계산한다.** 시간과 거리를 모델이 쓰게 두지 않는다.
- 가짜 데이터를 진짜로 바꿀 때마다 데모 흐름을 처음부터 끝까지 한 번 돌려 본다.

## 6. 위험과 대비

| 위험 | 대비 |
|---|---|
| ⚠ 미해결 충돌(D3·D10, 샌드박스 배치): 승인 API 가 에이전트 프로세스에 닿거나 무인증으로 공개된다 | 03 §6 규칙. 승인 API 는 에이전트가 닿는 곳에 두지 않고 인증 계층 없이 공개하지 않는다. 배치 결정 전까지 공개 링크 금지 |
| OpenShell·NemoClaw 버전 차이로 예제가 안 돈다 | 0단계에서 버전부터 확인. 설치된 버전의 문서를 따른다 |
| API 키 승인이 늦다 | 0단계에서 바로 신청. 키가 필요 없는 출처(국가유산청)와 파일 자료부터 진행 |
| 구청 게시판 구조가 제각각이다 | 한 구부터. 안 되면 데모용 게시물을 손으로 모아 수집본에 넣는다 |
| 포스터 인식이 부정확하다 | 확신도 낮은 항목은 비운다. 본문과 다르면 충돌로 표시. 데모용 포스터는 미리 결과를 확인 |
| 도보 경로 서비스의 경유지·한도 문제 | 결과를 저장해 재사용. 안 되면 직선 거리 어림과 "예상 시간" 표시 |
| L40S에 모델이 다 안 올라간다 | 임베딩·리랭커·비전을 우선. 가드와 경량은 호스팅으로 |
| 응답이 느리다 | 진행 표시. 데모 구간은 결과를 미리 저장해 두고, 조건을 바꾸는 장면만 실시간 |
| 데모 당일 외부 사이트 장애 | 수집본으로만 돌아가게 한다. 녹화 영상 준비 |
| 크레딧 소진 | 심사 기간분을 먼저 떼어 둔다. 쓰지 않을 때 인스턴스를 멈춘다 |
| 키 유출 | 공개 전 이력 검사. 유출되면 바로 재발급 |
| 범위가 넘친다 | `01_FEATURE_SPEC.md` 7장의 최소 묶음부터. P2는 마지막에 |
| 근거 없는 이야기가 나간다 | 근거 번호 없는 문장을 내보내지 않는 검사를 코드로 건다 |
