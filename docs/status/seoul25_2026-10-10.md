## 발견 (사람 판단 필요)

1. **"주변 행사"가 서울 전체가 됐다.** 채팅 묶음의 행사는 일정 날짜에 맞는 행사 전부이고, 거리나 구로 거르지 않는다(4개 구일 때 99건, 25개 구 244건). 잠실 일정의 첫 행사가 서초구, 가장 많은 구가 종로구(51)다. 4개 구일 때는 대상이 좁아 문제가 드러나지 않았다.
   - 제안: 일정 장소의 구(좌표가 있으면 거리)를 기준으로 거르거나 정렬하고, 장소를 모르면 서울 전체를 쓰되 그렇게 했다고 표시한다.
   - 묶음을 다루는 Stage 4 T434 와 같은 파일(`backend/chat.py`)이라 함께 정하는 것이 좋다.
2. **행사 화면의 검색 응답이 크다.** 25개 구에서 3.25MB, gzip 후 818KB 다. 공개 서비스의 북미발 송출 무료량은 월 1GiB 라 행사 검색 약 1,300회 분량이다. 원인은 `excluded` 19,342건 전체를 싣는 것이다(채팅 묶음은 이미 20건 + 사유별 개수로 줄였다: 881KB, gzip 83KB).
   - 제안: 행사 화면 API 도 같은 요약을 쓴다. 계약이 바뀌므로 결정이 필요하다.
3. 새 구 장소 좌표가 없다(롯데월드·잠실역) — Stage 4 T417(서울 API 장소 좌표 자동 부착, D25)이 다룬다.
