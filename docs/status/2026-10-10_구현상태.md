## ⚠ 알고 있어야 할 한계·결정 대기
- **D14(실록 DOCTYPE 처리)는 아직 "초안 — 사람 확인 대기"(H3).** 673개 파일 전부 읽히는 것은 확인했지만 사람 승인 전이다. 코드는 이 결정대로 동작한다.
- D15(보충 1·2 포함) · D16 · D17 · D18 · D19 · D20 · D21 · D22 · D23 은 승인됨. D15 보충 3(캐시 목표를 "저장된 결과의 재요청 변동 0" 으로 읽음)은 사용자 위임으로 코디네이터가 정한 것이다.
- D21 낮 시간 범위는 승인된 08:00~20:59 그대로 — "9시" 를 모델이 21:00 으로 내도 09:00 으로 바뀌고 `AMPM_ASSUMED`(확인 필요)로 남는다. 넓히기(07:00~22:59)는 H10 검수 때 실제 사례로 다시 본다.
- D22 연도 추정은 날짜별 독립이라 한 여행이 두 해로 갈릴 수 있다("10/5, 10/15" 를 10/10 에 받으면 2027·2026). `YEAR_ASSUMED` 로 드러나며 여행 기간 입력으로 고칠 수 있다.
- 입력 폴더 읽기 전용은 정책이 아니라 `chmod` 로만 보장된다(샌드박스 경로, 같은 uid 라 풀 수 있음).
- 서울 API 키로 받은 행사는 공공누리 1유형(출처 표시). Tavily 약관의 결과 저장·재사용 조건은 명시 조항을 찾지 못했다(사람 확인, `docs/spikes/web_search.md`).
- 스냅샷은 시점 자료(2026-10-10)라 오래되면 다시 만든다.
- 행사 수집·실록 수집은 호스트에서만 돈다(의도). 공개 서비스로 띄울 때는 속도 제한·요청 크기 제한이 앞단에 필요하다(`docs/guides/EVENTS_CATALOG.md`).
- "없다"는 "실록에 없다/행사가 없다"는 뜻이 아니다. 색인은 4개 구 키워드 기사만, 카탈로그는 수집한 출처만 담는다.
