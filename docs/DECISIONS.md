## D1 — 샌드박스 안에는 키를 두지 않는다 (2026-10-04)
- **결정**: 추론은 `inference.local` 로만 호출한다. `NVIDIA_API_KEY` 는 호스트 셸 env 와 OpenShell 게이트웨이 provider 에만 존재한다.
- **계기**: MaintQ D143 에서 실측 — 게이트웨이가 요청을 가로채 키를 주입하므로 샌드박스에 키가 필요 없다.
- **대안**: 샌드박스 env 로 키 주입 — 에이전트가 유출·오용할 수 있어 기각.

## D2 — 에이전트 도구의 쓰기는 draft 생성뿐 (2026-10-04)
- **결정**: 상태 전이(승인·반려·확정)는 사람 전용 API 에만 둔다. 신원은 서버가 주입한다.
- **계기**: MaintQ D10·D81·D154 에서 이어받음.
- **대안**: 에이전트가 직접 확정 — 사람 게이트가 무너져 기각.

## D3 — 도메인 무관 core/ 와 domains/<name>/ 슬롯 분리 (2026-10-04)
- **결정**: 미션 공개 전에 `core/`(llm·hitl·guard·audit·policy_proposer)를 완성하고, 당일에는 `domains/<name>/` 만 채운다. `mcp_server` 와 `backend` 는 프로세스를 분리하고 서로 import 하지 않으며, 공유 로직은 `core/` 에 둔다.
- **계기**: 미션이 10/7 당일 공개되고 산업이 정해지지 않았다. 사전 준비 기간(3~4일)에 도메인과 무관한 부분만 만들 수 있다.
- **대안**: MaintQ 코드를 복사해 시작 — 도메인 용어와 결정 159개가 딸려 와서 기각. NVIDIA 권장 디렉터리 구조 — 문서·build 페이지에서 찾지 못함.


## D4 — policy_proposer 의 입력은 우리 audit 기록(audit/v1)이다 (2026-10-06)
- **결정**: `core/policy_proposer` 는 `core/audit` 의 `AuditEvent`(JSONL 한 줄에 하나, `schema: "audit/v1"`)만 입력으로 받는다. OpenShell 슈퍼바이저 로그는 별도 어댑터(`core/policy_proposer/openshell_log.py`)가 audit/v1 의 `net` 관찰 이벤트(`source: "openshell"`)로 바꿔서 넣는다. proposer 본체는 OpenShell 로그 형식을 모른다. 어댑터가 해석하지 못한 줄은 버리고 건수만 보고한다. 추측해서 파싱하지 않는다.
- **계기**: ① OpenShell 로그 형식을 문서로 확인하지 못했다. 근거는 0.0.116 실측 몇 줄뿐이고 L7 줄은 생략된 인용만 있다. openshell 은 0.0.x 라 형식이 바뀔 수 있다. ② 관찰 대상(접속·파일·도구) 중 도구 호출은 MCP 서버 안에서만 보인다. OpenShell 로그에는 도구 이름이 없어 셋 중 하나밖에 덮지 못한다. ③ 우리 형식은 테스트로 고정할 수 있어 초안 출력이 결정적이다.
- **대안**: (a) proposer 가 OpenShell 로그를 직접 파싱 — 형식 미확인·도구 기록 없음으로 기각. (b) 두 형식을 모두 직접 수용 — 분기가 늘고 형식 변경 시 본체까지 깨져 기각. (c) OpenShell OCSF(JSON) 출력을 입력으로 — 존재 미확인. 확인되면 어댑터만 바꾸면 되고 D4 는 그대로다.

## D5 — core/llm 은 기능별 provider·모델 라우팅, 동시 호출, 키 풀을 지원한다 (2026-10-06)
- **결정**: `core/llm` 을 Sprint 1 의 선택 태스크(T303)로 만든다. 호출은 기능 이름으로 한다(`feature → provider·model` 설정 매핑). provider 별 동시성 상한(`Semaphore`)으로 한 provider 의 정체가 다른 기능을 막지 않게 하고, provider 당 키 여러 개를 라운드로빈으로 돌리며 429·오류가 난 키는 잠시 쉰다. 설정에는 키 값이 아니라 **env 변수 이름**(예: `NVIDIA_API_KEY_A`)만 적는다. 키 값은 코드·설정·리포에 두지 않는다(D1).
- **적용 범위**: 이번에는 호스트에서 실행하는 코드가 `.env`·셸 env 의 키를 읽는 경로만 만든다. 샌드박스 안에서는 D1 에 따라 `inference.local` 로만 호출하고 키는 게이트웨이 provider 에만 둔다. 게이트웨이의 다중 provider·모델 라우팅 지원은 문서로 확인(CLAUDE.md 규칙 4)한 뒤 붙인다. 설정 구조는 env 변수 이름 대신 게이트웨이 provider 이름으로 바꿔 끼울 수 있게 만든다.
- **계기**: 기능마다 다른 모델을 쓰고 병목 없이 동시에 부르려는 요구. 기능 목록은 10/7 미션 공개 후 정해지므로 `feature1`·`feature2` placeholder 로 만들고 `# TODO` 를 남긴다.
- **대안**: 단일 모델·단일 키 고정 — 기능별 모델 선택과 처리량 요구를 못 채워 기각. 샌드박스 안에 키 풀 주입 — D1 위반으로 기각. 기능 목록 확정 후 구현 — 당일 일정이 빠듯해 기각.
- **SCOPE 영향**: `docs/SCOPE.md` 의 "지금 안 만들 것"에서 `core/llm.py` 를 뺀다.

## D6 — core/llm 은 백엔드(api | local)를 전환하되 키는 provider 단위로 분리하고 자동 폴백은 하지 않는다 (2026-10-06)
- **결정**: 로컬 모델이 안 뜰 때를 위해 `core/llm` 에 백엔드 스위치를 둔다. 백엔드는 `LLM_BACKEND_<FEATURE>` > `LLM_BACKEND` > `api` 순으로 정하고 값은 `api`·`local` 만 허용한다(빈 값·대소문자 변형은 거부). **키는 백엔드와 무관하게 provider 단위로 따로 둔다** — api 는 `api_key_envs`, local 은 `local_api_key_envs`(비어 있어도 됨)를 쓰고, 두 목록이 같은 변수를 가리키면 거부한다. 키 풀과 동시성 세마포어는 `(provider, backend)` 별로 분리한다. 백엔드는 클라이언트 생성 시점에 고정한다. local 인데 `local_base_url` 이 없으면 시작 시 거부하고 조용히 api 로 넘어가지 않는다. **자동 폴백(실패 시 다른 백엔드로 재시도)은 만들지 않는다.** 로컬 백엔드는 호스트 경로 전용이다(D1: 샌드박스 안은 `inference.local` 만).
- **계기**: "로컬 Nemotron 이 안 뜨면 환경변수 하나로 API 로 넘어가게" 요청에 대해, 환경변수 하나로 키까지 바꾸면 기능별로 다른 키를 쓰는 D5 설계와 충돌한다는 지적. 그래서 전환 대상을 키가 아니라 엔드포인트로 한정했다. 이 PC 는 GPU 가 없어(`nvidia-smi` 없음) API 가 사실상 기본이다.
- **대안**: 환경변수 하나로 api 키까지 교체 — 기능별 키와 충돌해 기각. 실패 시 자동으로 다른 백엔드로 재시도 — 요청 본문이 의도치 않게 외부(api)로 나갈 수 있고 어느 쪽으로 갔는지 추적이 흐려져 기각(전환은 운영자가 명시적으로 한다). 백엔드를 호출마다 env 로 다시 읽기 — 실행 중 엔드포인트가 바뀔 수 있어 기각.
- **한계**: `local_base_url` 의 루프백 제한과 실제 HTTP transport 는 아직 없다(transport 구현 시 함께 처리). 로컬 엔드포인트 값은 문서 미확인 가정이다.

## D7 — 외부 자료는 호스트 수집기가 모으고 에이전트는 로컬 색인만 읽는다. policy.yaml 은 사람만 고친다 (2026-10-07)
- **결정**: 실록 XML·TourAPI·서울 열린데이터광장 수집은 호스트에서 실행하는 오프라인 수집기(`domains/kcontext/ingest/`)가 한다. 공공데이터 키는 호스트 셸 env 의 **변수 이름**(`DATA_GO_KR_SERVICE_KEY`, `SEOUL_OPENAPI_KEY` — 이름은 제안)으로만 참조한다. 결과는 `var/` 아래 로컬 색인·JSONL 로 저장하고, 에이전트 쪽(파이프라인·MCP 도구)은 이것만 읽는다.
  에이전트·dev 는 `deploy/openshell/policy.yaml` 을 수정하지 않는다(훅이 막는다). 사람이 추가한 `kakaomap_mcp` 항목은 샌드박스 도입 시점까지 미실측으로 두고, Sprint 2 코드는 이 항목에 의존하지 않는다.
- **계기**: ① 샌드박스 이미지는 Sprint 2 의 "지금 안 만들 것"이다. ② 외부 API 가 느리거나 한도에 걸릴 때를 대비해 핵심 자료를 로컬 색인으로 준비한다(AGENT_CONTEXT 7·8). ③ 키가 에이전트 프로세스에 들어가지 않는다(D1 과 같은 취지). ④ 정책 허용 항목은 실측(ALLOWED/DENIED)이 있어야 의미가 있는데(규칙 2), 실측은 샌드박스가 있어야 할 수 있다.
- **대안**: 에이전트가 실행 중에 API 를 직접 호출 — 샌드박스 허용 목록·provider 주입이 문서로 확인되지 않았고 이번 범위 밖이라 기각(다음 스프린트에 다시 검토). 키를 설정 파일에 기록 — 규칙 1 위반이라 기각. 미실측 항목 삭제 — 사람이 추가한 의도(카카오 호출 위치)가 정리되기 전이라 보류.

## D8 — 로컬 색인은 SQLite FTS5(trigram)로 시작하고 벡터 검색은 인터페이스 뒤로 미룬다 (2026-10-07)
- **결정**: 청크와 출처 메타(이름·위치·URL·원문 구절·수집일·등급)를 SQLite 한 파일에 저장하고 FTS5 `trigram` 토크나이저로 찾는다. FTS5 가 없는 빌드거나 검색어가 3자 미만이면 LIKE 로 찾는다. 검색은 `Retriever` 인터페이스로 감싸서, Nemotron 임베딩·리랭커는 키·NIM 이 확인되면 같은 인터페이스 뒤에 붙인다.
- **계기**: 표준 라이브러리만으로 바로 돌아가야 한다. 한국어는 형태소 분석 없이 trigram 으로 부분 일치를 잡을 수 있다. 임베딩은 API 키·엔드포인트(블로커)가 필요하다.
- **대안**: 처음부터 벡터 DB — 의존성과 키 블로커 때문에 기각. 파일 grep — 출처 메타 질의와 지역 필터가 어려워 기각.

## D9 — 도보 시간은 지도 엔진 값을 우선하고, 추정값은 추정이라고 표시한다 (2026-10-07)
- **결정**: 도보 거리·시간 공급자 우선순위는 ① PlayMCP 카카오맵 MCP(서버에서 호출할 수 있다고 확인된 경우) ② OSM 기반 도보 엔진 ③ 직선거리 × 우회 계수 ÷ 보행 속도 추정. ③의 결과는 `estimated: true` 를 달고 화면에 "예상 시간"으로 표시한다. 모델이 시간을 어림잡지 않는다. 네이버 Directions 는 자동차 전용이라 쓰지 않는다.
- **계기**: AGENT_CONTEXT 6장 "숫자는 지도·경로 엔진 값만"과 CONTEXT_STORY_ROUTE 6.3 "최소 구현: 직선 거리 추정, 화면에 예상 시간"을 함께 만족해야 한다. 카카오맵 MCP 는 카카오 로그인·본인인증이 필요해서 서버 호출 가능 여부가 미확인이다.
- **대안**: 추정 없이 지도 엔진이 준비될 때까지 경로를 안 냄 — 데모 경로가 통째로 막혀 기각. 추정값을 표시 없이 사용 — 사용자를 속이게 되어 기각.

## D10 — 화면용 API 는 backend 에, 파이프라인은 별도 프로세스로 돌리고 결과 파일만 주고받는다 (2026-10-07)
- **결정**: 프론트가 부르는 `/api/*`(읽기·채팅·사람 승인)는 `backend/` 에 둔다. backend 는 `domains`·`mcp_server` 를 import 하지 않는다. 채팅 요청이 오면 backend 가 `python -m domains.kcontext.pipeline.run` 을 **별도 프로세스**(`APP_PROCESS_ROLE=agent`)로 실행하고, 그 프로세스가 쓴 출력 묶음(`kc-bundle/v1`, JSON 파일)과 audit JSONL·hitl draft 를 읽는다. 상태 전이(승인·반려)는 backend 의 review 라우터에서만 한다(D2). 에이전트 쪽 산출물(출력 묶음·audit 기록)은 draft 와 같은 "제안" 지위이고 상태 전이를 담지 않는다. 사용자가 일정에 넣는 동작(`user_state`)은 이번 스프린트에서 화면 상태로만 다룬다.
- **계기**: CLAUDE.md 는 backend 를 "사람 전용 승인 API"로 정했는데, 프론트에는 읽기·채팅 API 가 더 필요하다. D3 의 프로세스 분리를 지키면서 도메인 로직을 backend 에 끌어오지 않는 방법이 필요하다.
- **대안**: 세 번째 프로세스(화면용 앱 서버) — 프로세스·포트가 늘어 기각. backend 가 `domains` 를 직접 import — 사람 전용 프로세스에 에이전트 코드가 들어와 D2·D3 경계가 흐려져 기각. 파이프라인을 MCP 서버 안에서만 실행 — 에이전트 런타임(NemoClaw) 연결이 이번 범위 밖이라 기각.

## D11 — 지도는 SVG 투영으로 먼저 그리고 타일·SDK 는 선택으로 붙인다 (2026-10-07, 구현 후 승인)
- **결정**: 프론트 map 모듈은 위경도를 화면 좌표로 투영해 SVG 로 그린다(배경 타일 없음, 외부 요청 없음). 카카오맵 JS SDK 나 OSM 타일은 키·도메인 등록·이용약관이 확인되면 같은 모듈의 렌더러로 추가한다.
- **계기**: 프론트는 번들러·외부 CDN 없이 돈다. 지도 SDK 는 키 발급·도메인 등록(사람 선행)이 필요하다. 목업이 이미 SVG 좌표계로 그려져 있고, map 모듈이 이 방식으로 구현되었다.
- **대안**: 처음부터 카카오맵 JS SDK — 키·도메인 등록 블로커로 기각. OSM 공개 타일 서버 직접 사용 — 이용 정책 미확인으로 기각.

## D12 — 구청 행사는 Tavily 검색 + LLM 추출로 보조 수집한다. 호스트 전용·초안 등급·인용 검증 필수 (2026-10-07, 사람 승인)
- **결정**: TourAPI·서울 열린데이터광장(D7)이 못 채우는 자치구(중구·마포구·강남구) 단위 행사를, 호스트 수집기가 Tavily Search 로 공식 도메인에서 찾아 LLM 으로 구조화한다. ① 검색은 `include_domains` 에 **사람이 승인한 도메인**(구청 공식 도메인, 사용자가 승인한 공식 연결 사이트·공식 블로그)만 넣고, 응답 URL 은 `allow_url_prefixes`·`disallow_path_prefixes` 로 한 번 더 거른다(`domains/kcontext/data/web_sources/*.json`, 사람이 확인한 값만, `status: confirmed` 가 아니면 그 구는 건너뛴다. robots.txt 가 막는 곳을 사람이 허용한 경우 그 사실을 `note` 에 남긴다). ② 추출 결과의 `quote`(원문 구절)가 가져온 본문에 **실제로 있어야** 레코드가 된다 — 없으면 버리고 problem 으로 센다. 제목·날짜·장소는 LLM 이 만든 값이 아니라 `quote` 에서 확인되는 값만 쓴다. ③ 본문은 D7 의 주입 차단(`inject.screen`)을 먼저 통과한다. ④ 레코드는 `fetched_from="web"`, 출처 `tier="C"`, `status` 는 확인 못 하면 `"unknown"` 이고, 화면에는 "검색 수집 · 미확인" 딱지로 나가며 사람 승인 전에는 일정 추천의 근거로만 쓰고 확정 사실로 말하지 않는다. ⑤ 키(`TAVILY_SEARCH_KEY`)는 호스트에서만 읽는다 — 셸 env 가 우선이고, 없으면 레포 `.env` 의 이 키 하나만 보충한다(`os.environ` 은 바꾸지 않는다, D1·D7). 샌드박스·policy.yaml 은 건드리지 않는다. ⑥ 호출 수 상한(`--max-calls`, 기본 30)을 코드에 둔다. ⑦ Tavily 응답 원문·가져온 본문은 커밋하지 않는다(`raw/` gitignore). 저장은 정규화 레코드와 짧은 `quote`·URL 뿐.
- **계기**: 공공데이터 API 는 구 단위 소규모 행사를 덜 담는다. 구청 사이트를 구마다 파서로 긁는 것은 유지 비용이 크고 샌드박스 정책을 늘려야 한다. Tavily 는 도메인 제한·기간 제한·본문 반환(공식 문서 확인, 2026-10-07)을 지원하고 월 1,000 크레딧(basic 검색 1)이 무료다.
- **대안**: 구청 사이트별 HTML 파서 — 구 25개 × 사이트 개편마다 깨져 기각. 샌드박스 안에서 직접 크롤링 — `network_policies` 를 늘려야 해 D7·규칙 2 와 충돌해 기각. 추출값을 `quote` 검증 없이 사용 — LLM 이 날짜·장소를 지어낼 수 있어 기각. 포스터 이미지 읽기(비전) — 범위 밖, 후속.
- **구현 규칙(검토 반영, 2026-10-07)**: quote 는 200자 이하이고 제목·날짜·장소는 제목 앞 80자·뒤 120자 안에서만 확인한다. 날짜는 quote 에 연도가 적혀 있으면 그 연도만, 연도가 없으면 — 게시일(`posted_date`)이 확인됐으면 게시일 기준 규칙(아래)을, 확인되지 않았으면 수집 대상 달의 연도와 같을 때만 — 인정한다("2025년 제10회"·"2025 정동야행"·"'25년" 처럼 날짜와 떨어져 적힌 연도 표기도 연도로 보고, 글에 연도가 둘 이상이면 연도 없는 월·일은 인정하지 않는다). C·D 출처는 공식(S·A·B) 값이 있는 필드에서는 충돌을 만들지 않고 caveat 로만 남기며, 취소·변경 정보는 적용하지 않는다. 날짜·장소를 C·D 출처에서만 채운 경우 값은 보여 주되 딱지를 "확인됨"으로 올리지 않는다. 월·연도 없이 일만 적힌 날짜("16일 저녁")는 본문에서 quote 가장 가까이(앞뒤 150자, quote 안의 날짜 제외)에 있는 연-월-일이 LLM 이 낸 게시일(`posted_date`)과 같고 수집일을 넘지 않을 때만, 게시일 이후 가장 가까운 그 일자로 보충하며(월 없는 일자는 같은 달 → 다음 달, 연도 없는 월·일은 게시연도, 게시일보다 60일 넘게 앞서면 다음 해) 레코드의 `source.locator` 에 "날짜 게시일 기준 추정"을 붙이고 `source.published` 에 게시일을 기록한다. 판정은 이를 caveat 로 보여 준다. "3일간"·"1일 3회"·"30일 이내"·"5일장"·"1박2일"·"총 3일" 같은 기간·횟수 표현은 일자로 보지 않는다. "지난 16일"은 게시일 이전 가장 최근 16일, "지난달 16일"은 전달로 읽는다. 게시일은 "작성일·등록일·게시일" 라벨이 붙은 날짜가 하나뿐이면 그것, 라벨이 없으면 quote 와 가장 가까운 날짜인데 다음 날짜와 거리 차가 5자 미만이면(이웃 행) 쓰지 않으며, quote 가 본문에 여러 번 나오면 모든 출현에서 같아야 한다. 판정 출력으로 나가는 모든 외부 문자열(제목 전 언어·장소·설명·출처 이름·위치·인용)은 주입 검사를 거친다. 합성 fixture 로 만든 레코드는 `synthetic=true` 이고 색인에 넣지 않는다.
- **열린 질문**: Tavily 이용약관의 결과 저장·재사용 조건 — 명시 조항을 찾지 못했다(원문 확인은 사람이, `docs/spikes/web_search.md`). 웹 레코드의 화면 표시 문구("검색 수집 · 미확인")와 색인에 들어간 텍스트의 소비 쪽 처리(`core.guard.wrap`)는 파이프라인(T216)·MCP 도구(T217) 단계에서 붙인다 — 그 전에는 파이프라인이 `fetched_from="web"` 을 화면 경로에 넣지 않는다. `EventRecord.fetched_from` 의 `"web"` 은 계약에 반영했다(`sprint-2.md` T201 절 포함).

## D13 — 공개 행사 카탈로그는 수집 레코드와 분리하고, 사실은 출처 근거와 함께 "모르면 모른다"로 둔다 (2026-10-07)
- **결정**: 사용자에게 보이는 행사는 `domains/kcontext/catalog/` 의 `EventEntry` 다. 수집 단계 레코드(`EventRecord`)·D12 검색 수집과 별개이며, 여러 출처의 관찰값(`Observation`)을 묶어 만든다.
  ① **모르는 값은 비우거나 `unknown`** — 무료·예약 불필요·영어 지원·외국인 참여 가능을 출처가 적지 않았으면 추정하지 않는다. 영어 홈페이지가 있다는 사실(`site_english_page`)과 행사 진행 언어를 구분한다.
  ② **대상 지역은 개최 장소로만** 정한다(출처가 준 자치구 → 주소 → bbox). 주최·운영기관 이름은 근거가 아니다. 장소가 여러 곳이면 회차마다 `in_target` 을 둔다.
  ③ **묶기**: 같은 외부 id, 또는 장소+기간+행사명 유사도가 함께 맞을 때만(주최가 같으면 느슨하게 0.5, 아니면 0.8). **같은 체계의 외부 id(예: `seoul_cult:`)인데 값이 다르면 다른 행사다.** 행사명만 같거나 주최만 같으면 합치지 않고, 기간이 겹치지 않으면 다른 회차로 남긴다. 같은 원천에서 재배포된 자료는 독립 출처로 세지 않고, 제보·수기·AI 추출은 독립 출처 수에 넣지 않는다.
  ④ **충돌·취소**: 공식 값끼리 우선순위(주최 홈페이지 > 공식 API > 보도자료)와 더 최근 수정으로만 해결하고, **해결되지 않으면 검증 상태를 `conflict` 로 두고 그 필드의 값은 비워 "확인 필요"로 보인다(후보 값은 충돌 목록에만 남는다).** 예약·언어·참여조건은 주최·공식 API·보도자료 출처의 값만 쓴다(제보·SNS·AI 추출은 채우지 않는다). 취소·연기는 공식 출처가 알릴 때만 반영한다.
  ⑤ **수집 실패·게시글 삭제·빈 결과는 취소가 아니다**: 실패하면 기존 데이터를 그대로 두고 오류·재시도(5분 → 최대 6시간)만 기록한다. 보이지 않는 관찰값은 지우지 않고 "마지막 확인 시각"만 오래된 채로 둔다.
  ⑥ **이동시간은 경로 서비스의 결과만** 쓴다: 추가 이동시간 = 앞→행사 + 행사→뒤 − 앞→뒤(같은 교통수단). 하나라도 얻지 못하면 "이동시간 확인 필요". 직선거리를 도보시간으로 쓰지 않는다(D9) — 거리 기반 추정 공급자를 두지 않았다.
  ⑦ **AI 의 역할**은 추출·충돌 발견·요약·추천 이유 설명이며, 날짜·지역·참여조건·경로 계산은 코드가 한다. AI 출력은 행사 id·근거 링크·사실에 있는 숫자로 검증한다(`catalog/grounding.py`). **현재 이 검증기에 연결된 AI 경로는 없다**(LLM 연결 T223 이월) — 검증기와 규칙만 준비돼 있다.
  ⑧ **제보는 검토 대기**로만 저장하고 사람이 승인해야 반영한다(승인돼도 공식 출처가 아니라 `needs_check`). 관리자 API 는 `X-Admin-Token`(미설정이면 닫힘)이고 신원은 서버가 정한다(D2).
  ⑨ backend 는 `domains` 를 import 하지 않고 `python -m domains.kcontext.catalog.api` 를 별도 프로세스로 호출한다(D10). 공공데이터 키는 수동 재수집 호출에만, 그 출처가 쓰는 키 하나만 넘긴다 — 키를 `.env` 에서 고르는 것은 backend(`catalog_runner`)이고 자식 프로세스는 `.env` 를 읽지 않는다. 프론트의 `?base=` 는 같은 출처 경로나 루프백 8000 포트만 받는다(관리자 토큰·일정이 다른 서버로 가지 않게). 카탈로그 쓰기는 파일 잠금으로 직렬화한다.
- **계기**: 외국인 관광객이 "여행 날짜·숙소·기존 일정에 맞는 중구 행사와 참여 방법"을 확인하고 일정에 더하는 흐름이 필요하다. 이 흐름에서 가장 큰 위험은 끝났거나 바뀐 행사, 참여할 수 없는 행사를 확정처럼 보여 주는 것이다.
- **대안**: `EventRecord` 에 필드를 계속 덧붙임 — 계약이 엄격(모르는 키 거부)하고 출처별 근거·충돌을 담을 수 없어 기각. 값이 비면 가장 그럴듯한 값으로 채움 — 사실 지어내기라 기각. 직선거리로 도보시간 추정 — D9 위반이라 기각.

## D14 — 실록 XML 은 외부 SYSTEM DOCTYPE 만 허용하고 ENTITY·내부 서브셋은 거부한다 (2026-10-07, 초안 — 사람 확인 대기)
- **결정**: 실록 수집기(`domains/kcontext/ingest/sillok`)는 파일 앞부분(4KB)의 DOCTYPE 을 검사해 ① `<!DOCTYPE 이름 SYSTEM "파일이름.dtd">` 형태(외부 DTD 를 가리키는 SYSTEM 선언 하나)만 통과시키고, ② `<!ENTITY`·`<!ATTLIST`·`<!ELEMENT` 같은 선언이나 내부 서브셋(`[` … `]`)이 있거나 PUBLIC 선언이거나 SYSTEM 값이 URL·경로(`/`·`:`·`..` 포함)이면 그 파일을 건너뛰고 `skipped_files` 에 이유를 남긴다. DOCTYPE 이 없는 파일은 통과한다. ③ 파서는 표준 `xml.etree.ElementTree.iterparse` 만 쓰고, 외부 DTD 를 읽지 않으며(표준 `ElementTree` 는 가져오지 않는다) 엔티티를 풀지 않는다. 검사는 파싱 전에 하며, 정규식이 아니라 expat 의 선언 핸들러(DOCTYPE·ENTITY·ELEMENT·ATTLIST·NOTATION)로 문맥(주석·따옴표)까지 판단한다. XML 선언의 encoding 은 UTF-8 만 허용한다. SYSTEM 값에 `..` 가 있어도 거부한다. 검사에서 거른 파일은 파서에 넘기지 않는다.
- **계기**: 실측(`docs/spikes/sillok.md`) — 673개 파일 전부가 `<!DOCTYPE level2 SYSTEM "history.dtd">`(또는 level1)를 가지고, `<!ENTITY` 는 0건이다. 계획(T209 "DOCTYPE 이면 건너뜀")대로면 실제 파일을 전부 거부해 DoD 를 못 채운다. 위험은 DOCTYPE 자체가 아니라 엔티티 확장(billion laughs)·외부 엔티티(XXE)·내부 서브셋이므로, 그것만 막는다.
- **대안**: DOCTYPE 이면 무조건 거부 — 실제 자료 673개 전부 거부돼 기각. 검사 없이 파싱 — 확장 공격이 들어간 파일이 섞이면 막을 곳이 없어 기각. `defusedxml` 도입 — 의존성 추가, 외부 SYSTEM DTD 만 있는 이 자료에는 위 선검사로 충분해 보류(자료가 늘면 재검토).
- **한계**: 4KB 안에 DOCTYPE 이 끝나지 않으면(내부 서브셋이 길면) 거부한다. 실측 자료에서는 DOCTYPE 이 첫 줄이다. 한문 원문만 있는 자료라 지명 태그 매칭은 별도 문제다(T209 의 `sillok_keywords`).
- **구현 중 확인(2026-10-07)**: 실제 파일 5개(`2nd_wqa_106`·`wra_104`·`wra_105`·`wrb_104`·`wrb_105`)는 보충 한자를 서로게이트 쌍 두 개의 문자 참조(`&#55381;&#56892;`)로 적어 XML 1.0 구문 오류가 난다. 짝이 맞는 쌍만 하나의 코드포인트 참조로 합쳐서 파싱하고, 짝이 안 맞는 서로게이트는 그대로 거부한다. 이 보정은 엔티티를 정의·확장하지 않으므로 D13 의 거부 규칙과 충돌하지 않는다. 673개 파일 전부가 읽힌다(기사 id 형식이 다른 38건은 제외, docs/spikes/sillok.md).
- **영향**: `docs/sprints/sprint-2.md` T209 의 "DOCTYPE·ENTITY 이면 건너뜀"과 DoD 를 이 결정으로 고쳐 읽는다(스프린트 문서 본문은 사람이 확인한 뒤 수정).

## D15 — 일정 이해는 결정적 파라미터·예산 안 재시도·결과 캐시로 안정화하고, 시간 예산은 프론트 상한에서 거꾸로 정하며, 실패를 일반 답으로 덮지 않는다 (2026-10-09, 사람 승인)
- **결정**:
  ① `core/llm` 의 feature 설정에 호출 파라미터 `params`(허용 목록: temperature·top_p·seed·max_tokens·response_format·reasoning_effort)를 둔다. 값은 공급자가 받아들인다고 실측(docs/spikes/llm_params.md)한 것만 넣는다. 일정 이해는 `schedule` feature 를 쓴다(없으면 `chat`).
  ② **시간 예산은 프론트 요청 상한 100초에서 거꾸로 정한다**: backend 파이프라인 한도 = 90초, 파이프라인 안 LLM 예산 = 75초, LLM 1회 한도(`timeout_s`) = 기준선 p95 × 1.5(20~75초 사이로 자름). 숫자는 sprint-3 §6.4 표를 따른다.
  ③ LLM 응답이 실패·빈 응답·JSON 아님·형식 틀림이면 **같은 백엔드로 1회** 다시 부르되, **남은 LLM 예산이 LLM 1회 한도 이상일 때만**(첫 시도가 일찍 실패했을 때만) 부른다. 다른 백엔드로 넘어가지 않는다(D6).
  ④ quote 검증을 통과한 LLM 결과는 `var/cache/schedule/` 에 캐시한다. 키는 정규화한 입력 글·여행 기간·프롬프트 해시·LLM 설정 파일 해시·모델 덮어쓰기 env 다. 캐시 결과를 쓰면 묶음에 `schedule.source: "cache"` 와 원래 생성 시각을 남기고 화면은 "이전 결과 재사용"으로 표시한다. 평가는 캐시를 끈다.
  ⑤ 일정 문장으로 판별됐는데 LLM 이 (재시도 뒤에도) 실패해 앵커를 얻지 못했거나 파이프라인이 한도를 넘기면, 일반 챗봇으로 넘기지 않고 고정 문구("일정을 지금 정리하지 못했어요. 잠시 뒤 다시 보내 주세요.")로 답한다. LLM 이 정상으로 답했는데 앵커가 0개(일정이 아님)일 때만, 남은 예산이 LLM 1회 한도 이상이면 일반 챗봇으로 간다. 입력·결과 조합별 동작은 sprint-3 §6.5 표다.
- **계기**: 같은 문장이 일정 3개/2개/일반 답 폴백으로 갈렸고(README), 시간 사슬이 어긋나 프론트(80초)가 backend(90초)보다 먼저 끊을 수 있었다.
- **대안**: 캐시 없이 파라미터만 — 공급자가 결정성을 보장하지 않으면 같은 결과를 약속할 수 없어 기각. 실패 시 일반 챗봇 폴백 유지 — 일정 실패가 엉뚱한 답으로 가려지고 지연이 두 배가 되어 기각. 예산과 무관한 고정 재시도 — 프론트 한도를 넘어 기각. 규칙 대체 추출 — 재측정(T311)이 목표에 못 미칠 때 별도 결정으로 다시 검토(보류).
- **기준선 값(T307, `eval/BASELINE.md`)**: p95 26.5초 → LLM 1회 한도 40초. 재시도는 첫 시도 경과 ≤ 35초일 때만, 일반 챗봇 진입은 파이프라인 경과 ≤ 55초일 때만. 파라미터는 temperature 0 만 켠다(seed·response_format 은 효과 불명으로 끔, `docs/spikes/llm_params.md`).

## D20 — OpenShell 샌드박스는 선택 기능으로 둔다. 필수 보안은 앱 코드의 장치로 보장한다 (2026-10-09, 사람 결정)
- **결정**: 해커톤 이후 제품(backend · 파이프라인 · 화면)은 OpenShell 없이 호스트에서 돌고, 그대로 완성 기준(포트폴리오 데모)을 만족한다. OpenShell 관련 파일(`deploy/openshell/`, `scripts/gateway_setup.sh`·`kculture_practice.py`, `core/policy_proposer/`)은 지우지 않고 **선택 기능**("샌드박스 시연 — 해커톤 당시 22항목 실측")으로 남긴다. 문서는 필수·선택을 나눠 쓴다(`deploy/README.md`, README, `docs/guides/SETUP.md`).
- **필수 보안(OpenShell 과 무관, 계속 지킨다)**: ① 키는 `.env`(gitignore)·셸 env 에만, 허용 목록 이름만 읽는다(규칙 1, D1) ② 에이전트 역할 프로세스에는 허용 목록 env 만 넘긴다(D7 ③, `backend/story_runner.py`) ③ 외부 글은 신뢰하지 않는 입력으로 감싸고 주입을 막는다(`core/guard`, `judge/inject`) ④ 에이전트 쓰기는 초안까지, 확정은 사람 전용 API(D2) ⑤ 도구·판정 기록은 `core/audit` 에 남긴다. ⑥ 외부 자료는 호스트 수집기만 받는다(D7).
- **계기**: 코드 확인(2026-10-09) — `backend/`·`domains/`·`frontend/` 어디에서도 OpenShell 을 호출하지 않는다. 파이프라인은 고정 순서 코드이고 LLM 은 후보 추출만 하며 출력이 실행되지 않고 도구도 없다. 그래서 OpenShell 이 막아 주는 위협(에이전트의 외부 유출·임의 쓰기)이 현재 구조에는 거의 없다. 대회가 끝나 "OpenShell 사용"이 목적이 아니게 됐다.
- **대안**: (a) 완전히 제거 — 코드는 깔끔하지만 해커톤 결과물의 핵심 증거(실측 22항목)가 사라져 기각. (b) 제품을 샌드박스 안으로 옮김 — 완성 기준에 필요 없는 일이라 기각(SCOPE "지금 안 만들 것").
- **다시 볼 때**: LLM 에 도구(파일·네트워크)를 쥐여 주거나, 공개 서비스로 띄우거나, NemoClaw/OpenClaw 로 에이전트를 샌드박스 안에서 돌릴 때 — 그때는 OpenShell 을 다시 필수로 검토한다.
- **영향**: CLAUDE.md 의 "OpenShell 사용이 목적" 문구와 `docs/08_OPENSHELL_POLICY.md` 의 "필수 기술" 문구는 이 결정으로 고쳐 읽는다. `scripts/preflight.sh` 는 openshell·게이트웨이 없음을 FAIL 로 세는데, 이것도 선택 항목(WARN)으로 바꿔야 한다(후속).
