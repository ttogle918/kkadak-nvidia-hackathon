# /stage — 스테이지 실행

Stage `$ARGUMENTS` 를 실행한다. 자동 파이프라인(구현 → 회귀 → 검토 → 커밋) 후 **수동 체크리스트를 출력하고 멈춘다.**

## Step 1 — 태스크 확인

`docs/sprints/` 최신 파일로 스프린트 N 을 확인하고 `sprint-{N}.md` 에서 해당 스테이지의 태스크와 명세를 읽는다.
이전 스테이지가 미완료면 경고하고 사용자에게 확인한다.

## Step 2 — dev 병렬 실행

태스크 수만큼 `dev` 에이전트를 **동시에** 호출한다. 각 호출에 전달:

```
태스크: T{id}
스프린트 N / 스테이지 M
명세: docs/sprints/sprint-{N}.md 의 해당 절
범위: 만질 디렉터리
병렬 중인 다른 태스크: [목록] — 같은 파일 수정 주의
지켜야 할 규칙: CLAUDE.md 절대 규칙 번호 / D번호
```

## Step 3 — eval-runner: 회귀 검증

`eval-runner` 를 호출한다. 회귀 명령은 **`CLAUDE.md` 의 "회귀 테스트" 절이 기준**이다 — 이 문서에 명령을 박아 두지 않는다.
실패하면 해당 태스크의 dev 만 재실행하고 그 부분만 재검증한다. 전체 스테이지 재실행은 불필요하다.

## Step 4 — reviewer: 설계·보안 게이트

`reviewer` 를 호출한다. 전달: 스테이지 번호 · 변경 파일 전체 · 적용 태스크 목록. D 번호 범위는 전달하지 않는다(전 범위를 읽는다).
FAIL 이면 수정 후 reviewer 만 재실행 — **커밋 불가.** 보안 항목 위반은 수정 전 커밋 불가.

## Step 5 — 커밋

reviewer PASS 즉시 변경 파일만 `git add` 해서 커밋한다.
메시지: 한 줄 요약 + 태스크별 핵심 + `Sprint {N} / Stage {M}` + 검증 결과. 커밋 트레일러는 세션이 지정한 attribution 지침을 따른다.
커밋 후 `docs/sprints/sprint-{N}.md` 에 완료 기록(날짜 · 커밋 해시 · 태스크별 구현 파일 · 회귀 결과)을 추가한다.

## Step 6 — 수동 체크리스트 출력 후 대기

**이 단계가 핵심이다.** 자동 검증이 못 잡는 것을 사람에게 넘긴다.

```markdown
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ Stage {M} 자동 파이프라인 완료 · 커밋 {해시} · 회귀 {요약}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
## 수동 확인
### 기능
- [ ] {기능}: {확인 방법 — URL·명령어까지}
### 사람만 판단 가능한 것
- [ ] {안전 문구 문안 / 매핑 정확성 / 시각 정합 / 데모 흐름}
### 회귀 위험
- [ ] {이번 변경이 건드린 기존 기능}
다음: 문제 없으면 /stage {M+1} · 버그면 내용 알려주기 · 마지막이면 /done
```

## 재개

`/stage 2 resume` — `sprint-{N}.md` 의 완료 상태를 확인하고, 커밋이 이미 됐으면 Step 6 부터 재개한다.

## 에러 처리

| 상황 | 처리 |
|------|------|
| dev 실패 | 해당 태스크만 실패 처리, 나머지 병렬 태스크 계속 |
| 회귀 FAIL | 실패 태스크의 dev 만 재실행 |
| reviewer FAIL | 커밋 보류, 수정 후 reviewer 재실행 |
| 병렬 파일 충돌 | 스테이지 재분리 필요 → `/sprint` 재실행 |
| 사람 승인 대기에 막힘 | 해당 태스크 보류하고 나머지 진행, 체크리스트에 명시 |
