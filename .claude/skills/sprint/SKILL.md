# /sprint — 스프린트 계획 수립

Sprint `$ARGUMENTS` 의 **계획만** 세운다. 코드 구현은 하지 않는다. 최종 계획은 pm·dev 평가까지 포함해 `docs/sprints/sprint-{N}.md` 에 기록한다.
번호가 없으면 `docs/sprints/` 의 최신 번호 + 1 (없으면 1).

## 사전 준비

계획의 재료: `docs/SCOPE.md`(반드시 / 지금 안 함) · `docs/DECISIONS.md` · `CLAUDE.md` · `docs/sprints/` 이전 로그 · `git log --oneline -15` · 실제 코드 존재 여부.
`docs/SCOPE.md` 가 비어 있으면 계획을 세우지 말고 사용자에게 범위부터 묻는다.

## Step 1 — pm: 스테이지 계획

`pm` 에이전트를 호출해 스테이지 배치와 **태스크별 상세 구현 명세**를 받는다. dev 가 추가 추론 없이 실행할 수 있을 만큼 구체적이어야 한다.

## Step 2 — dev: 현실성 평가

`dev` 에이전트를 호출해 평가한다 (구현은 시키지 않는다):
- [ ] 명세가 구현에 충분한가
- [ ] 병렬 실행 시 파일 충돌이 있는가
- [ ] 스테이지 내 숨은 순서 의존성이 있는가
- [ ] 막힐 수 있는 항목(사람 승인 대기 · 키/크레딧 · 게이트웨이/샌드박스 가동 · 데이터 라이선스)에 걸리는가

```markdown
| 스테이지 | TASK | 리스크 | 제안 |
|---------|------|--------|------|
```

## Step 3 — 계획 확정

수정이 필요하면 pm 에 재계획을 요청한다. 최종 계획을 `docs/sprints/sprint-{N}.md` 에 기록한다.

```markdown
## Sprint {N} 최종 실행 계획
| 스테이지 | 태스크 | 병렬 | 예상 결과물 |
```

## Step 4 — 사용자 확인

`Sprint {N} 계획 완성. 시작하려면 /stage 1` 을 안내하고 대기한다.

## 하지 말 것

- 코드 수정 (계획 단계다)
- `docs/SCOPE.md` 의 "지금 안 함" 항목을 태스크로 승격
- `docs/DECISIONS.md` 와 충돌하는 계획 — 충돌하면 먼저 결정을 추가한다
