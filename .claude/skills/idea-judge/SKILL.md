# /idea-judge — 아이디어 심사

`$ARGUMENTS` 가 있으면 그것을 **미션 문구 또는 후보 목록**으로 본다. 없으면 `docs/private/IDEAS.md` 의 후보 전체를 대상으로 하고, 미션 문구를 사용자에게 묻는다.
이 스킬은 의논을 돕는다. 결정은 사람이 한다 — 추천은 하되 하나로 못 박지 말고 이유를 남긴다.

## 입력 읽기

1. `docs/private/IDEAS.md` — 후보 목록, 팀 자산(예선작), 팀 구성, 공개 데이터 후보
2. 미션 문구 — 있으면 **미션이 허용하는 산업·주제 범위**를 먼저 뽑는다. 범위 밖 후보는 탈락
3. `CLAUDE.md` · `docs/SCOPE.md` — 현재 뼈대(core/)가 이미 해주는 것

## 1단계 — 탈락 필터 (하나라도 걸리면 탈락, 이유 한 줄)

| 필터 | 질문 |
|---|---|
| **if문 테스트** | 에이전트 부분을 if문·규칙으로 바꿔도 데모가 성립하는가? 성립하면 탈락 |
| **하루 구현** | 주어진 시간 안에 입력 → 에이전트 → 도구 → 사람 승인까지 끝까지 도는가? 데이터를 당일 구할 수 있는가? 라이선스는? |
| **미션 적합** | 미션 문구·교육 주제(에이전트 보안: NemoClaw·OpenShell)와 연결되는가? |
| **금지선** | 회사 내부 데이터·실명·거래처 정보가 필요한가? 사람 승인 없이 쓰기·제어가 필요한가? |

## 2단계 — 점수 (각 1~5, 근거 한 줄)

심사 기준을 그대로 쓴다. 근거 없는 5점 금지.

| 항목 | 보는 것 |
|---|---|
| ① NVIDIA 기술 활용 심도 | OpenShell 격리·정책, NemoClaw 에이전트, Nemotron, 스킬을 **각자 자리에** 쓰는가. 억지로 끼운 건 감점 |
| ② 실용성·산업가치·혁신성 | NVIDIA·고객사가 "우리 문제"라고 느끼는가. 사회적으로 필요한가 |
| ③ 완성도 | 데모가 끝까지 안정적으로 도는가. 실패 경로(not_found·주입 시도)도 보여줄 수 있는가 |
| ④ 커스터마이징·독창성 | 뻔한 챗봇이 아닌가. 보안 설계(최소 권한·사람 승인·비신뢰 입력)가 제품의 일부인가 |
| 재사용 | 뼈대(core/)와 예선 자산을 얼마나 쓰는가 — 클수록 하루 안에 끝낼 확률이 높다 |

가중치는 기본 ①②③④ 동일, 재사용은 보조(동점 처리)로 쓴다. 사용자가 가중치를 주면 따른다.

## 3단계 — 출력

```markdown
## 미션 해석
{허용 범위 한 줄 · 교육 주제와의 접점}

## 탈락
| 후보 | 걸린 필터 | 이유 |

## 점수표 (상위 5)
| 후보 | ① | ② | ③ | ④ | 재사용 | 합계 |

## 추천 3 (순위 + 한 줄 이유)
1. {후보} — {왜}
...

## 1순위 후보 상세
- **피칭 한 줄**: "..." (모델을 만드는 건 다음 단계, 우리는 오픈 모델 위에서 에이전트로 현장 문제를 안전하게 푼다 — 포지셔닝 유지)
- **데모 흐름**: 입력 → 에이전트가 쓰는 도구 → 사람이 승인하는 지점 → 막히는 공격 1건
- **if문 테스트 통과 근거**: 규칙으로 못 하는 부분이 무엇인가
- **가장 큰 리스크 2개와 우회안**
- **뼈대에서 가져다 쓸 것 / 새로 만들 것**

## 사람이 정해야 할 것
- {판단이 갈리는 지점 — 예: 안전 쪽 vs 현장 쪽 중 어디에 시간을 쓸지}
```

## 하지 말 것

- 점수를 근거 없이 올려 원하는 후보를 밀어주기
- `docs/private/IDEAS.md` 에 없는 데이터셋·도구가 "있다"고 단정하기 — 확인이 필요하면 "확인 필요"라고 쓴다
- 소요 시간을 지어내기
- 구현 시작 — 이후 흐름은 `/sprint`
