# /done — 세션 마무리

세션에서 한 일을 `docs/session_log/YYYY-MM-DD_HHMM_주요작업.md` 에 기록한다. 파일 이름 규칙·기록 형식·비밀 금지 규칙은 `/logger` 스킬과 같다(`.claude/skills/logger/SKILL.md` 를 따른다). 이 세션에서 `/logger` 로 이미 만든 파일이 있으면 그 파일을 최종본으로 갱신한다.
`/stage` 가 스테이지 단위 커밋을 처리하므로 `/done` 의 주 역할은 **로그와 결정 정합성 점검**이다.

## Step 1 — 커밋 안 된 변경 확인

`git status` · `git diff --stat HEAD`. 있으면 커밋 여부를 묻는다.

## Step 2 — 세션 정보 수집

`git log --oneline -15` · `git branch --show-current` 와 대화 내용에서:
- 날짜 · 브랜치 · 작업 범위 한 줄
- 완료 작업 (항목 + 주요 파일)
- **의논 내용과 결정 맥락** — 왜 이 방향인지, 검토하고 버린 대안. 가장 중요하다. 결과만 남기면 다음 세션에 같은 논의를 반복한다
- 이번 세션에 추가된 결정 (D번호)과 그 계기
- 트러블슈팅 — 증상 / 원인 / 해결 / 관련 커밋 (없으면 "없음")
- 다음 세션에 할 것 · 사람 승인 대기 항목의 변화

## Step 3 — 결정 정합성 점검

이번 세션에 결정이 추가됐으면:
- `docs/DECISIONS.md` 에 번호·계기·대안이 적혀 있는가
- `docs/CONTRACTS.md`(있다면) · `CLAUDE.md` 절대 규칙에 반영됐는가
- 계약이 바뀌었다면 회귀 테스트가 그것을 검증하는가
- 문서 어디에도 "D1~D{숫자}" 같은 범위를 박아 두지 않았는가 (낡아서 검토 범위가 조용히 좁아진다)

## Step 4 — 세션 로그 작성

```markdown
# {주요작업}
**일시**: YYYY-MM-DD HH:MM · **브랜치**: {branch} · **범위**: {한 줄}

## 완료
- {항목} — `{주요 파일}`

## 결정과 맥락
### D{N} — {제목}
- **계기**: / **대안**: {검토하고 버린 것과 이유}

## 트러블슈팅
### {증상}
- **원인**: / **해결**: / **커밋**: `{hash}`

## 검증 상태
- 회귀: {CLAUDE.md 회귀 절 기준 결과}

## 다음 세션
1. ...

## 사람 승인 대기
- [ ] ...
```

## Step 5 — 완료

세션 로그를 커밋하고(`docs: 세션 로그 {주요작업}`, 트레일러는 세션 attribution 지침) 아래를 출력한다:

```
✅ 세션 마무리
세션 로그: docs/session_log/{파일명}
다음: {다음 작업}
```
